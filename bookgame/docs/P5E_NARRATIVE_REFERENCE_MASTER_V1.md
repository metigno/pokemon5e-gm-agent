# P5E DIGITAL BOOKGAME — NARRATIVE REFERENCE MASTER V1

**Status:** LOCKED REFERENCE  
**Gold standard:** INTRO → M1  
**Applies to:** M2 → M12 narrative passes  
**Core rule:** **THE RUNTIME KNOWS. THE SCREENPLAY SHOWS. THE INTERFACE DOES NOT EXPLAIN THE ENGINE.**

## 1. Authority
1. `P5E_LIBROGAME_ENGINE_SOURCE_OF_TRUTH.md`
2. module design + production mapping
3. `NODE_SPEC` / runtime contracts
4. Pokémon canon for canonical NPCs
5. project roster descriptions for established original NPCs
6. this reference for player-facing narrative quality

Never rebuild validated mechanics merely to improve prose.

## 2. Narrator
- second person singular;
- present tense;
- observable/external;
- concise D&D-GM voice;
- no omniscient NPC thoughts;
- never dictate player emotions, intentions or dialogue;
- show known facts, visible facts, successful-check information and explicit NPC communication.

Routine nodes: 1–3 short paragraphs. Character beats: 2–5. Write for progressive/typewriter reveal.

## 3. Fiction → Mechanics → Fiction
The screenplay sets up the situation. Pokémon 5e resolves mechanics. The screenplay resumes from the actual result.

Never player-facing: resolver, runtime, engine, combat pack, stat block, flag, variable, node, stitch, branch, script, callback, selector, persistent state/roster, technical difficulty HARD/STANDARD, module M1/M2, beat, free-roam.

## 4. NPC characterization hierarchy
### Canonical/famous NPC
Use Pokémon canon first. Respect the character's age and current career stage. Never preload future achievements.

### Established project NPC
Use the project's written description/personality as local canon.

### Neutral/original NPC
Use a cinematic/fantasy archetype fitting profession and task, without caricature. Archetype never overrides established canon.

Show personality through behavior, priorities, vocabulary, humor and decisions.

## 5. The Five — locked characterization
- **Luke:** stubborn, lazy, proud, competitive; never abandons favorite Pokémon merely to optimize; tries to make them fit perfectly; loves force/impact and aggressive battling while remaining attached to his Pokémon.
- **Mattew:** partly Luke's antithesis; proud and stubborn but disciplined, technical and training-oriented; wants to understand how things work; loves Pokémon and does not see them as damage machines.
- **Daniel:** educated, structured, more rigid in behavior and morality; principled without becoming a generic over-analyst.
- **Edward:** stylish, likes Pokémon that deal damage, strong personal taste, does not care about others' judgment; philosophy partly similar to Luke.
- **Fab:** Trainer almost by chance; loves his Pokémon; does not obsess over optimization; wants to win with them.

**Shared lock:** friends before rivals. They tease one another constantly and all have a strong sense of humor. Five serious coworkers discussing tactics = wrong tone.

## 6. Dialogue
Use authored contextual topics: local area, Pokémon, rumors, people, dangers, jobs, organizations, recent events. Availability depends on knowledge, relationship, quest state, time, location, reputation, morality and prior dialogue.

NPC information quality is role-dependent: none / partial / complete. Nobody knows something merely because the plot needs exposition.

Social checks follow Pokémon 5e. Check type may be visible; DC stays hidden.

## 7. Wild Pokémon ecology
Encounter ≠ battle.

Wild Pokémon behave like fauna: timid, territorial, curious, predatory, social, solitary, herd/pack-based, defensive, protective, aggressive, cooperative or habituated to humans.

Before escalation, show observable signals: posture, gaze, distance, food/water access, young, group behavior, escape route.

When appropriate allow observe / avoid / help / interact / fight / capture.

Combat should emerge from escalation or player choice. **Different species require different behavior, not the same template with another species name.**

Ordinary wild Pokémon remain capturable according to Pokémon 5e. Never author an automatic capture.

## 8. Competition
An official presents rules in-world. A terminal displays registration/results. An opponent is a Trainer, never a technical ID.

Win and loss both need valid continuation. Trainer-owned registered Pokémon are not wild capture targets.

## 9. Hidden systems → visible consequences
- NPC schedule → the person is somewhere else doing something.
- quest expiry → posting becomes PRESO/CHIUSO; another person may have acted.
- relationship score → tone, trust, availability and later callbacks change.
- rank requirement → license reader/staff deny or grant access.
- world event → reports, routes, fauna, work and people visibly change.
- persistence → the world simply remains changed; never explain save/state persistence.

The world moves without the player.

## 10. Player choices
Choices describe intention/action, never technical effect.

Good: “Resto a distanza e osservo il suo comportamento.”  
Good: “Gli restituisco spazio e continuo lungo la strada.”  
Bad: “Attivo il ramo di de-escalation.”  
Bad: “Faccio il check che imposta il flag fauna_known.”

## 12. Scene review checklist
- narrator only exposes perceivable/known information;
- NPC voice follows canon/project/archetype hierarchy;
- personality is shown, not explained;
- NPC knowledge is plausible;
- choices describe actions, not engine effects;
- Pokémon 5e check semantics remain intact and hidden DC does not leak;
- wild encounter has species-specific behavior;
- non-combat route exists when ecologically sensible;
- combat engine remains authority over mechanical outcomes;
- win/loss/ignore/delay paths remain narratively valid where authored;
- persistent consequences are shown diegetically;
- world can progress without player intervention;
- text works as progressive/typewriter reveal;
- no player-facing engine terminology.

## 13. Definition of Done — narrative module
A module passes when:
1. mandatory beats exist in fiction without runtime leakage;
2. NPC voices are distinct and coherent;
3. ecology and battles respect Pokémon 5e;
4. choices do not promise mechanically unresolved outcomes;
5. win/loss/ignore/delay have valid consequences;
6. module transitions appear as travel, opportunities or world changes;
7. final player-facing scan finds no technical leaks;
8. prose works with progressive reveal.

## 14. Operational formula for M2→M12
**PRESERVE MECHANICS → FIND LEAKS → DETERMINE WHO CAN KNOW WHAT → REWRITE DIEGETICALLY → CHARACTERIZE → CHECK ECOLOGY → CHECK WIN/LOSS/IGNORE → BLACKLIST SCAN**

Preserve IDs, conditions, effects, checks, time costs, combat handoffs, quest state, schedules and persistence unless they genuinely conflict with the Source of Truth.
